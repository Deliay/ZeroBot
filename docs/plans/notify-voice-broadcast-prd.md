# 通知语音播报 —— 产品需求文档（PRD）

| 属性 | 值 |
|---|---|
| 需求名称 | 通知语音播报（群通知以指定音色追加语音播报） |
| 所属插件 | ZeroBot.Synthesize（播报能力与指令）、ZeroBot.Bilibili / ZeroBot.Weibo（触发点接入） |
| 状态 | 待评审 |
| 关联文档 | [技术方案](./notify-voice-broadcast-tech.md) |

---

## 1. 背景与目标

群内已可通过订阅指令开启 B 站开播、B 站动态、微博动态、直播间 SC、主播弹幕等文字通知。用户希望在通知发出时，额外收到一条用指定音色合成的语音播报，让通知「听得见」。

**目标：**

- 群内可通过指令开启/关闭通知语音播报，开启时指定语音合成别名（音色）。
- 开启后，该群已开启的下列通知在发送文字通知时，额外独立发送一条语音消息：
  - B 站开播
  - B 站动态
  - 微博动态
  - 直播间醒目留言（SC）
  - 主播弹幕
- 通知本身未在该群开启的，不产生语音播报（语音播报依附于既有通知链路，天然满足前置条件）。

## 2. 名词约定

| 名词 | 说明 |
|---|---|
| alias（别名） | 语音合成数据集别名，经 `/synthesize:dataset:{dataset-id}:{alias}` 绑定，见 `ZeroBot.Synthesize` |
| dataset-id | 后台语音训练服务（vtuber-training）的数据集 ID，别名解析的目标 |
| 语音播报 | 通知发出时追加发送的一条独立语音消息，内容为按模板生成的播报文本的合成语音 |

## 3. 功能需求

### 3.1 开启语音播报指令

- **指令格式：** `/动态语音播报:启用:{alias}`
- **示例：** `/动态语音播报:启用:小松绿`
- **权限：** 群管理员 / Sudoer / 拥有 `synthesize.voice-broadcast` 权限（沿用现有权限模型，与 `/B站动态`、`/直播SC` 等订阅指令一致）。
- **仅群聊可用。**
- **行为：**
  1. 校验 `{alias}` 已在语音合成别名表中绑定（`DatasetAliases` 存在该别名）；未绑定 → 回复提示「别名 {alias} 未绑定数据集，请先使用 /synthesize:dataset 绑定」。
  2. 记录「本群 → alias」的播报配置并回复确认，例如「已开启本群通知语音播报，音色：小松绿」。
- 同群重复开启：幂等；使用不同别名再次开启 = 更换音色（覆盖旧配置），回复确认。

### 3.2 关闭语音播报指令

- **指令格式：** `/动态语音播报:禁用`（兼容 `/动态语音播报:禁用:{alias}` 的多余参数形式，忽略参数）。
- **权限：** 同 3.1。
- **行为：** 移除本群的播报配置，回复确认，例如「已关闭本群通知语音播报」。
- 未开启过时关闭：幂等，回复确认即可，不报错。

### 3.3 语音播报触发与播报文本

开启播报的群，在以下通知**实际发送到该群**时，额外独立发送一条语音消息（与该通知的文字消息分为两条，语音在文字通知之后发送）：

| 通知类型 | 触发条件 | 播报文本模板 |
|---|---|---|
| B 站开播 | 该群已订阅直播间（`/直播状态:订阅`）且收到**开播**通知（下播不播报） | `噔噔咚，开始直播了哦。今天播「{直播标题}」。` |
| B 站动态 | 该群已订阅该 UP 主动态（`/B站动态:订阅`）且收到动态通知 | `{动态的文本内容}`（不含表情包、图片占位与链接等纯展示元素的文本） |
| 微博动态 | 该群已订阅该微博用户（`/微博:订阅`）且收到微博通知 | `{动态的文本内容}`（不含表情包、图片占位的文本） |
| 直播间 SC | 该群已订阅该直播间 SC（`/直播SC:订阅`）且收到 SC 转发 | `感谢{SC发送人}发送的{Price}元醒目留言，{SC内容}` |
| 主播弹幕 | 该群已订阅该主播直播间事件（`/主播直播间事件:订阅`）且收到主播本人弹幕转发 | `{弹幕文字}` |

细则：

- 表情包弹幕（无文字、仅表情图）不产生语音播报。
- 动态/微博文本按既有消息构建的纯文本提取逻辑取得（转发动态含转发人文本与被转文本），剔除图片、表情占位与 URL。
- 播报文本超过最大长度（默认 200 字，可配置）时截断后再合成，控制合成开销。
- 语音消息为独立一条，不 at 全体。
- 一条通知面向多个开启播报的群时，同一文本仅合成一次，分发到各群。
- 语音播报不消耗 `/学` 指令的用户每日合成额度（自动播报非用户主动行为）。

### 3.4 前置条件

- 「已开启 B 站通知的群才能收到播报」由实现天然保证：播报挂载在既有通知的发送链路上，群未订阅对应通知时该链路不会触达该群，开启播报但不订阅任何通知的群不会收到任何播报。

## 4. 非目标（本期不做）

- 按通知类型分别开关播报（开启后上述 5 类统一播报）。
- 入场事件、下播通知的语音播报。
- 语速/音量/语言等合成参数调节。
- 播报的频率限制与每日额度限制（仅以最大文本长度控制开销）。
- 私聊场景的语音播报。

## 5. 边界与异常

| 场景 | 行为 |
|---|---|
| 开启时 alias 未绑定数据集 | 提示绑定失败，不写入配置 |
| 开启后 alias 被改绑到其他 dataset | 下次播报即使用新 dataset（别名解析以播报时配置为准） |
| 开启后 alias 被移除（别名表删除） | 跳过播报并记录告警日志，文字通知不受影响 |
| 语音合成接口失败 / 超时 / 返回空 | 记录日志，跳过本次语音，**不影响文字通知发送** |
| 播报文本为空（如纯图片动态） | 跳过播报 |
| 多账号登录 | 与文字通知一致，遍历全部账号发送 |
| Bot 重启 | 播报配置持久化于配置文件，重启后自动恢复 |
| 语音发送失败（群不存在/被禁言等） | 沿用 `WriteManyGroupMessageAsync` 现有行为，仅记录结果，不中断后续通知 |

## 6. 配置与运维

- 播报配置持久化于既有 `synthesize-config.json`（热加载），新增字段向后兼容，旧配置文件无需迁移。
- 不新增环境变量；合成 endpoint 复用 `synthesize-config.json` 的 `endpoint`（`Z_VTUBER_TRAINING_ENDPOINT`）。
- 不修改任何线上配置文件，播报开关通过群内指令维护。

## 7. 验收标准

1. 群内发送 `/动态语音播报:启用:小松绿`（别名已绑定）→ 回复开启成功；`synthesize-config.json` 出现该群配置。
2. 群内发送 `/动态语音播报:启用:不存在的别名` → 回复未绑定提示，未写入配置。
3. 已订阅开播的群，主播开播 → 收到原文字通知后，额外收到一条独立语音，内容为「噔噔咚，开始直播了哦。今天播「{标题}」。」（小松绿音色）；下播时无语音。
4. 已订阅 B 站动态 / 微博动态的群，新动态到达 → 文字通知后收到动态纯文本的语音。
5. 已订阅 SC 的群，收到 SC 转发 → 文字通知后收到「感谢{发送人}发送的{Price}元醒目留言，{内容}」的语音。
6. 已订阅主播直播间事件的群，主播发弹幕 → 收到弹幕文字的语音；主播入场 → 无语音。
7. 未开启播报的群收到同样通知 → 无任何语音。
8. 开启播报但未订阅任何通知的群 → 无任何语音（满足前置条件）。
9. `/动态语音播报:禁用` 后 → 后续通知不再有语音，回复确认；重复禁用不报错。
10. 模拟合成接口不可用 → 文字通知正常送达，无语音，日志有记录。
11. 重启 Bot 后播报配置自动恢复。
