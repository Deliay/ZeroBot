# B 站主播直播间事件转发 —— 产品需求文档（PRD）

| 属性 | 值 |
|---|---|
| 需求名称 | 主播直播间事件转发（主播弹幕转发到 QQ 群） |
| 所属插件 | ZeroBot.Bilibili |
| 状态 | 待评审 |
| 关联文档 | [技术方案](./bilibili-anchor-event-forward-tech.md) |

---

## 1. 背景与目标

主播有时会在**自己的直播间**发送弹幕（回复观众、自言自语、发通知等）。这类弹幕混在观众弹幕中，群友无法及时看到。本需求将「订阅主播本人在其直播间发出的弹幕」实时转发到订阅的 QQ 群。

**目标：**

- 群内可通过指令订阅/取消订阅某个 B 站主播（按 mid）的直播间弹幕事件。
- 主播本人在其直播间发送弹幕时，Bot 自动将该弹幕转发到所有订阅群。
- 多个群可订阅同一主播，退订互不影响；全部退订后自动断开事件流。

## 2. 名词约定

| 名词 | 说明 |
|---|---|
| mid | B 站用户 UID（主播的用户 ID） |
| roomId | B 站直播间 ID，由 mid 通过 `/api/b/user/{mid}` 查询得到 |
| vtuber server | 内部 B 站数据服务（`Z_VTUBER_SERVER_ENDPOINT`），提供用户查询与直播事件 SSE |
| 主播弹幕 | `danmaku` 事件流中 `cmd == "DANMU_MSG"` 且发送者 `UserId == 订阅 mid` 的事件 |

## 3. 功能需求

### 3.1 订阅指令

- **指令格式：** `/主播直播间事件:订阅:mid`
- **权限：** 群管理员 / Sudoer / 拥有 `bilibili-anchor-event.subscribe` 权限（沿用现有权限模型，与 `/直播SC`、`/B站动态` 一致）。
- **行为：**
  1. 调用 `/api/b/user/{mid}` 校验 mid 并解析出 `roomId`、`uName`。
  2. mid 不存在或未被 vtuber server 收录（404 / 无 roomId）→ 回复提示「未找到该主播，请确认 mid 是否正确」。
  3. 订阅成功 → 记录 `mid → (roomId, 群集合)` 并回复确认，例如「已订阅主播 枝堇Sumire(1150976664) 的直播间弹幕，主播发弹幕时将转发到本群！」。
- 同一群重复订阅同一 mid：幂等，回复确认即可。

### 3.2 取消订阅指令

- **指令格式：** `/主播直播间事件:取消:mid`
- **行为：** 将本群从该 mid 的订阅群集合中移除；集合为空时移除该 mid 的订阅记录（事件流随之断开）。回复确认。
- 未订阅过时取消：回复确认即可，不报错。

### 3.3 弹幕事件转发

- 对每个有群订阅的 roomId，通过 SSE 订阅 `GET /api/b/live/{roomId}/event/subscribe?type=danmaku`。
- 收到 `DANMU_MSG` 事件后，**仅当发送者 UserId 等于订阅的 mid 时**（即主播本人发言）才转发，观众弹幕一律忽略。
- **转发格式（文本）：**

  ```
  枝堇Sumire 的弹幕 [小粉螈 19]：
  弹幕内容
  ```

  粉丝牌信息缺失时省略 `[]` 部分（沿用 SC 转发的格式约定）。
- 表情包弹幕（`MemeUrl` 非空）：文本后附带该表情图片。
- 转发到该 mid 的全部订阅群；**不 at 全体**（与 SC 转发一致）。
- 每个 roomId 仅维持一条 SSE 长连接；连接断开/出错后自动重连；某 mid 全部群退订后断开对应连接。

## 4. 非目标（本期不做）

- **主播入场事件转发：** vtuber server 的 `interact` 事件流（`INTERACT_WORD_V2`）payload 为 protobuf 编码（`pb` 字段），解析成本高，本期不实现，列为后续迭代候选。
- 普通观众弹幕转发、弹幕关键词过滤、弹幕频率限制。
- 礼物 / SC / 开播通知转发（已有或属于其他需求）。

## 5. 边界与异常

| 场景 | 行为 |
|---|---|
| mid 不是已收录主播 | 订阅时提示失败，不写入配置 |
| 主播未开播 / 直播间无弹幕 | 正常状态，SSE 长连接静默等待，不产生消息 |
| SSE 断连、出错 | 自动重连（退避约 5s），不丢订阅关系 |
| 事件反序列化失败 | 记录告警日志，跳过该条，不中断事件流 |
| 同一主播被多个群订阅 | 每个订阅群都收到转发；单群退订不影响其他群 |
| Bot 重启 | 从配置恢复订阅关系并自动重连 |

## 6. 配置与运维

- 订阅关系持久化于既有 `bilibili-config.json`（热加载），新增字段向后兼容，旧配置文件无需迁移。
- 不新增环境变量；复用 `Z_VTUBER_SERVER_ENDPOINT`。
- 不修改任何线上配置文件，订阅关系通过群内指令维护。

## 7. 验收标准

1. 群内发送 `/主播直播间事件:订阅:1150976664` → 回复订阅成功；配置中出现对应记录。
2. 该主播在自己直播间发送弹幕 → 5 秒内订阅群收到转发，格式符合 3.3。
3. 其他观众发送弹幕 → 群内无转发。
4. 两个群分别订阅同一主播 → 两群均收到转发；A 群 `/主播直播间事件:取消:1150976664` 后仅 A 群不再收到，B 群不受影响。
5. 全部群退订后，对应 SSE 连接断开（日志可证），配置记录清除。
6. 订阅一个未被收录的 mid → 回复提示，未写入配置。
7. 重启 Bot 后订阅关系自动恢复。
